# Stele: specification

## 1. What this is

Stele is the finished document-web browser for the 486 that [`stele-charter.md`](stele-charter.md)
founds: one static i486 musl binary that fetches, parses, styles, lays out and renders the document
web, with no JavaScript by construction, and fits on a 1.44 MB floppy. The charter is the
constitution: its kill conditions (K1–K4), its covenant (C1–C11) and its record "What Stele Speaks"
(C2's adopted amendments) define what Stele is and what it renders. This file points to the charter
and does not copy it. [`stele-build-brief.md`](stele-build-brief.md) is the process document; the
charter wins on principle, the brief on process.

**Non-goals** (charter K3): no JavaScript, no Java, no plugins, no updater, no telemetry. They are not
declined features: the document AST has no variant that could carry them.

## 2. Principles

Every node keeps these. They are AGENTS.md's non-negotiables, with the charter's covenant behind them.

1. **No JavaScript, by construction.** The document AST (`src/dom/`) is a closed sum type with no
   variant for executable anything (charter C3). No node adds one.
2. **The 1.44 MB floppy (1,474,560 bytes) is the real ceiling**, tighter than A2's 2,000,000-byte
   hard fail. Every dependency, feature and decoder is priced against it. Every node PR reports the
   `stele-i486` size and its delta, measured from CI's A2 line, never guessed.
3. **CI compiles the i486 build.** The cross build (`-Zbuild-std` in the pinned `monolith-builder`
   image) and the `accept` job run in CI, not in a session.
4. **Golden discipline.** Goldens are byte-compared. A changed render is measured and pixel-verified
   as correct before it is blessed; a golden is never re-blessed to turn CI green, and a regression is
   never blessed away.
5. **Test-first, root-cause-first.** Every behavioural change lands with a failing test first; every
   bug is root-caused before it is fixed. Three failed fixes in a row mean the design is questioned.
6. **The dialect is amended, never drifted.** Whatever makes Stele speak something new (a CSS
   property, an element, a behaviour) is first recorded in the charter's C2 adopted-amendments record,
   with its size price, in the spec PR that plans the node, before the code lands.
7. **The covenant holds**: one static binary (C1), `panic=abort` (C4), plain-file state (C6), fully
   attested dependencies (C8), one pinned toolchain (C9), the speed budget (C10), build provenance
   (C11).

## 3. State

**Done** (everything on the default branch). REPORT.md's status: M0–M5, the hardening core, the X11
backend, Acid2 "composes" (not byte-exact). Since REPORT.md was written: the A5z speed gate, the A2
floppy warning (A2 warns over the floppy and fails over 2,000,000 bytes), client-side image maps
(charter K2) and the bootstrap of the A7 audit tools from `ci/`. REPORT.md is a dated release summary
and is behind on these.

**Planned**, in this order (each becomes a node once an issue asks for it):

0. **Look at migrating the UI toolkit to Protolith**, before the work below gets far. Protolith is a
   pixel, window and input library over the X11 wire protocol and the Linux framebuffer, `std` only
   and without `unsafe`; Stele's own X11 and framebuffer backends (`src/backend/`) do that work today.
   See decision D1.
1. **A7 attestation ceremony** (`cargo vendor` + `cargo-auditable` + `cargo-audit`), building on the
   audit-tool bootstrap.
2. **Cookie-jar file persistence** (charter C6): the jar exists and is wired into HTTP; it is not
   saved across invocations.
3. **Rendering fidelity nits**: `&nbsp;` as a non-collapsing space; CMYK and 16-bit JPEG; APNG.
4. **Charter M6, Transcript + Provenance** (charter C7).

**Later, not planned**: the Lua chair (C5), the Transcript pane, the no-libc spike, the K1 iron run on
real 486 hardware.

## 4. Architecture

One crate, `stele` (library and binary), Rust 2021 on the nightly pinned in `rust-toolchain.toml`.
Dependencies are few and priced (`Cargo.toml`): taffy with trimmed features, gif, jpeg-decoder, png,
rustix.

- `src/dom/`, `src/dom_util.rs`: the HTML parser and the closed document AST.
- `src/style/`, `src/stylesheets.rs`: CSS parsing, cascade, computed style, media queries.
- `src/text/`: text metrics, the embedded Terminus bitmap font (`terminus_glyphs.rs` is generated by
  `tools/gen-terminus-glyphs.py` from `third_party/terminus-font/`) and the transliteration fallback.
- `src/img/`, `src/images.rs`, `src/bg_images.rs`: GIF, JPEG and PNG decoding and image loading.
- `src/layout/`: the box tree, block and inline flow, floats, tables and image maps; taffy does the
  box math.
- `src/fetch/`: `file:`, `data:`, `about:`, HTTP/1.1, HTTPS, URLs, cookies, the attestation page (`attestations_data.rs`
  is generated by `tools/gen-attestations.py`; `assets/attestations.html` is its page).
- `src/backend/`, `src/surface/`: the tty, framebuffer, X11 and headless raster backends, the chrome
  and the address bar, and the memory surface.
- `src/main.rs`, `src/lib.rs`, `src/browser.rs`, `src/form.rs`, `src/frames.rs`: the binary, the
  library root, the browser loop, forms and frames.
- `tests/` (integration tests against the library's public API or the binary), `fixtures/` (HTML and
  image inputs), `goldens/` (byte-compared reference renders, `.txt` and `.png`).
- Build and CI: `.cargo/`, `targets/` (the i486 target JSON), `rust-toolchain.toml`, `accept.sh` (the
  definition of done, checks A1–A7), `ci/`, `.github/workflows/`, `tools/render-gallery.sh`.

`docs/graph.yaml` holds the gate, the paths out of scope and the nodes. Out of scope:
`docs/superpowers/` (design and plan docs of merged packets, kept as history), `JOURNAL.md` (the
frozen log; the merged node PRs and the graph are the log now) and `LICENSE`.

## 5. Node spec template

Every node spec `nodes/<ID>-<name>.md` has the title `# <ID> — <name>`, the header row
`| Track | Deps | Unlocks | Size |`, a line `**Owns:**` naming in backticks the globs of the paths the
node creates or changes, a line `**Resolves:** #<n>` when the node is drafted from an issue, and these
headings:

- `## Purpose`: why the node exists and what it builds on.
- `## Tests`: the test files the node adds and its red target (a command that exits non-zero before
  the node's change and 0 after).
- `## Changes`: numbered, each naming the criterion it produces (`*<ID>-AC-n.*`), and, for a change
  to the dialect, the C2 amendment it carries out.
- `## Gate`: the criteria, one line each, `- **<ID>-AC-<n>** — <statement> *Verify:* <command>`,
  numbered from 1.
- `## Risks`: including the expected size price against the floppy.

## 6. Open decisions (defaults apply until the owner changes them)

- **D1. Migrating the UI toolkit to Protolith.** The owner asked to look at it before other work gets
  far; what it covers is not settled. Default: the first node is an evaluation, not a migration. It
  compares Protolith with `src/backend/x11.rs` and `src/backend/fb.rs` (and the input handling that
  goes with them) on what Stele uses, the `stele-i486` size delta against the floppy, the covenant
  (C1, C3, C8 attested and vendored, C9 the pinned toolchain, no `unsafe`) and the existing tests and
  goldens, and reports a recommendation. The owner decides on the migration from that report; the
  migration itself is planned as later nodes only then.
- **D2. Who writes a golden.** The role guard counts `goldens/` as test data, so the tester writes
  goldens and the implementer cannot. Default: the tester writes the expected golden first where it
  can be written by hand (a `.txt` golden); a `.png` golden that only the new render can produce is
  blessed by the tester after the implementer's change, measured and pixel-verified as principle 4
  asks, and the reviewer checks that measurement.
- **D3. Tests that need a private item.** Default: new tests go in `tests/` against the library's
  public API, or through the binary (`CARGO_BIN_EXE_stele`). A criterion that can be tested only
  through a private item is put to the owner before the node goes on.

- **D4. A5u outside CI.** A5u (`goldens/chrome-basic.png`) fails in every checkout whose path is not
  CI's container path, because `--chrome` puts the fixture's absolute `file://` URL in the address bar.
  It passes in CI. Default: it is listed in `gate.known_red`, so local gate runs are judged without it,
  and CI's `build` job stays the evidence that it passes; a node that makes the chrome screenshot
  independent of the checkout path removes it from the list. Alternative: plan that node first.

## 7. Conventions

- Branches: `node/<ID>-<name>` for a node, `spec/<topic>` for a spec change. Work outside the graph
  keeps AGENTS.md's packet rules.
- Spec files (AGENTS.md's **Spec files:** line) change only in spec PRs: a dialect amendment to the
  charter's C2 record, and a decision for `DECISIONS.md`, land in the spec PR that plans the node.
- Sizes: S under a day, M two or three days, L more.
- A node is done when its Gate's criteria pass, the gate passes in CI on its PR together with the
  i486 build and the `accept` job, its PR reports the `stele-i486` size and delta, and the spec
  checkers print `PROBLEMS 0`.
